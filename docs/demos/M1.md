# M1 demo: two instances in different subnets ping each other

M1 is the thinnest end-to-end slice of Nephos:

- a VPC with two subnets, plus one real instance in each subnet;
- a ping that travels between the subnets as real packets;
- state that survives an appliance restart;
- a reset that leaves nothing behind.

The automated version of this demo is `tests/m1-e2e.sh`. It runs in the native Ubuntu 24.04 CI job and through `make e2e`. This page is the manual version. It is also the checklist for the Windows 10 QA that M1 requires.

## Prerequisites

- Docker. On Windows that means Docker Desktop with the WSL2 backend.
- A clone of this repository on Linux, or on WSL2's ext4 filesystem.
- The images and CLI built from the commit under test. Run these inside Linux or WSL:

  ```bash
  make dev-ami     # Ubuntu 24.04 development AMI
  make appliance   # nephos-appliance:dev
  make build       # bin/nephos for Linux and WSL
  make cross       # dist/nephos_windows_amd64.exe for PowerShell
  ```

- No existing `nephos` container or `nephos-data` volume.
  - `nephos up` would reuse them, and the instance names below would collide with whatever is already there.
  - If one exists, run `nephos down --purge` first. **This deletes its data.**

Docker Desktop shares one Docker engine between Windows and WSL. The `nephos` container is therefore the same one whichever shell starts it. Run the PowerShell pass and the WSL pass one after the other, never at the same time. Each pass ends with a purge.

## The demo

In WSL or Linux, use `bin/nephos`. In PowerShell, copy `dist\nephos_windows_amd64.exe` to a folder of your choice as `nephos.exe`, and run `.\nephos.exe` there. The arguments are identical in both shells.

```bash
nephos up
nephos vpc create lab --cidr-block 10.0.0.0/16
nephos subnet create a --vpc lab --cidr-block 10.0.1.0/24 --availability-zone local-1a
nephos subnet create b --vpc lab --cidr-block 10.0.2.0/24 --availability-zone local-1b
nephos instance run one --subnet a --wait
nephos instance run two --subnet b --wait
nephos console one -- ping -c 3 10.0.2.4     # .4 is the first assignable address (.0-.3 are reserved)
nephos console one -- sh -c 'echo hello > /root/marker'
nephos down
nephos up
nephos console one -- ping -c 3 10.0.2.4     # state and addresses survived the restart
nephos console one -- cat /root/marker       # prints hello: the instance root survived
nephos reset
nephos vpc list                              # empty
nephos down --purge                          # end of the pass; asks for confirmation
```

```text
$ nephos console one -- ping -c 3 10.0.2.4
Nephos serial/exec console (authenticated network-access exception)
PING 10.0.2.4 (10.0.2.4) 56(84) bytes of data.
64 bytes from 10.0.2.4: icmp_seq=1 ttl=63 time=0.155 ms
...
3 packets transmitted, 3 received, 0% packet loss, time 2054ms

$ nephos down
Nephos appliance stopped; data volume preserved

$ nephos up
Nephos appliance ready at http://127.0.0.1:7788

$ nephos reset
Removing all instances, subnets and VPCs in workspace default...
Workspace default is empty; the leak check found no Nephos objects.
```

What each step proves:

- **`ttl=63`:** the packet crossed exactly one router, the VPC router namespace. The subnets are not on a shared bridge.
- **The second ping and `cat /root/marker`:** `down` and `up` kept the instances, their private IPs and their root filesystems.
- **`nephos reset`:** it exits 0 only when every instance, subnet and VPC is gone and the in-appliance leak check is complete and clean. That check covers namespaces, links, nftables, Podman containers, processes and leases.

## Windows 10 manual QA record

M1's acceptance requires the demo to pass manually on Windows 10 with WSL2 and Docker Desktop. Run it once from **PowerShell** with `nephos.exe`, and once from **WSL** with `bin/nephos`.

For each pass, record:

- the commit;
- the versions of Windows, Docker Desktop and WSL (`wsl --version`);
- the result.

| Pass | Date | Commit | Windows / Docker Desktop / WSL | Result | Notes |
|---|---|---|---|---|---|
| PowerShell (`nephos.exe`) | | | | not yet run | |
| WSL2 (`bin/nephos`) | | | | not yet run | |

A pass succeeds when:

1. every command exits 0;
2. both pings show `0% packet loss`;
3. `cat /root/marker` prints `hello` after the restart;
4. `nephos reset` prints the clean leak-check line;
5. `nephos vpc list` prints nothing.

If a step fails, keep the terminal output and `docker logs nephos`, then open an issue.

Host-side nftables cannot be inspected from WSL2 under Docker Desktop. That check is recorded as N/A here. The native CI run covers it.
